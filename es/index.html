Un workflow. Cualquier agente de código.

Aqorin ejecuta tu workflow de ingeniería con Claude Code, Codex, OpenCode o Pi, y guarda el Run, sus comprobaciones y su evidencia. El agente que ya usas hace el trabajo, con sus propias fortalezas. Tu configuración sigue siendo tuya.

npm i -g @aqorin/cli

Leer la guía

Versión 0.5.0, demostrada en macOS con Apple silicon y en Linux (Ubuntu, x86_64). Licencia MIT.

Tu proceso vive en la carpeta de configuración de un agente.

Cada agente de código trae sus propios agentes, comandos, skills, hooks y permisos. Un workflow real (especificar, implementar, revisar, corregir) acaba escrito para un solo runtime y sostenido por un prompt que le pide al modelo que se acuerde.

Claude Code
.claude/, CLAUDE.md
Codex
~/.codex/config.toml, AGENTS.md
OpenCode
opencode.json, .opencode/
Pi
~/.pi/agent/

En Aqorin el workflow es un fichero y el runtime se elige por rol. Antes de ejecutar nada, el plan dice qué runtime lleva cada rol y qué puede hacer cumplir Aqorin allí. Lo que no puede hacer cumplir lo llama orientativo (advisory).

Cómo va un Run

Aqorin es dueño del workflow, del estado del Run y de su evidencia. El runtime es dueño de la ejecución, a su manera.

  1. 1

    Escribe la tarea una vez

    Un fichero de tarea guarda la petición y los comandos que la deciden. El workflow, uno de los incluidos o tu propio fichero en .aqorin/workflows/, dice qué pasos se ejecutan, en qué orden y adónde vuelve el trabajo cuando una revisión pide cambios. Los dos se validan y se congelan con el Run.

  2. 2

    Deciden las comprobaciones, no el modelo

    Con un Acceptance Plan, Aqorin ejecuta él mismo los comandos y solo su código de salida decide la validación. Un paso cuyas comprobaciones fallan no pasa. Sin él, el Run es orientativo, y el resultado lo dice en vez de presentarse como validado.

  3. 3

    Los agentes escriben dentro del Run

    En macOS, y en Linux (con bubblewrap), el sandbox propio de Aqorin está activo por defecto para Claude Code, OpenCode y Pi, en Runs y en chats. Codex mantiene su propio sandbox. Donde el sandbox no se puede montar, el Run se rechaza en vez de ejecutarse sin él.

    Escrituras rechazadas

    • El resto del repositorio, su .git y .aqorin
    • Tus otros proyectos, los que añadiste
    • Tus claves y credenciales
    • La configuración de tu shell, de git y de los gestores de paquetes
    • Los ajustes de los propios agentes de código
    • Las carpetas habituales del PATH, como /opt/homebrew/bin

    Sin límite

    • Las lecturas: un agente en el sandbox aún puede leer un secreto
    • La red
    • Lo que haga un servidor MCP
    • Un proyecto que no has añadido, cachés y ficheros temporales
  4. 4

    El Run sobrevive a la terminal

    Cada transición es un evento en el registro del propio Run, comprobado por el reducer del motor. Cierra la terminal y el Run sigue ahí: síguelo, respóndele, reanúdalo, reintenta o vuelve a planificar un paso que falló. La recuperación reinicia el paso, así que un efecto puede repetirse.

Reglas para el motor, no para que un modelo las recuerde

  1. Tu configuración sigue siendo tuya

    Los agentes, comandos y ajustes de Aqorin viven en su propia capa con espacio de nombres. Nunca escribe la configuración de tu runtime, tu PATH ni tus enlaces simbólicos.

  2. Tu runtime sigue como está

    Sigue usando claude, codex, opencode o pi exactamente como hoy. Aqorin es un comando aparte que usas cuando quieres.

  3. Las invariantes viven en el código

    El orden de los pasos, los presupuestos, la revisión obligatoria y las transiciones válidas las hace cumplir el reducer, no se le piden a un modelo en un prompt.

  4. El estado es del Run

    Una sesión del runtime es un intento. El Run es duradero, así que un runtime que se cae no borra lo que pasó.

  5. Cada garantía dice dónde se aplica

    La aplica Aqorin, el runtime, el kernel, o nadie, y entonces se dice orientativa. Nada se eleva en silencio.

  6. Un Aqorin. Varios proyectos. Workflows independientes.

    Añade tus proyectos una vez y síguelos todos desde una TUI o una CLI: Runs de varios proyectos trabajan a la vez, cada uno con su runtime, en su repositorio, con sus worktrees, su sandbox y sus pull requests, como si cada uno tuviera su propio Aqorin.

  7. Sin mínimo común denominador

    La mejor primitiva de cada runtime se usa de forma nativa, se emula con seguridad, se degrada a la vista o se rechaza. No se quitan funciones por simetría.

Lo que no afirma

Dicho aquí con el mismo peso que las funciones, porque conviene saberlo antes de instalar.

Plataforma
Demostrado en macOS con Apple silicon, y en Linux — Ubuntu 26.04 en x86_64, con bubblewrap como sandbox y un paso restringido de Claude Code advisory allí — desde la 0.4.0 (la 0.3.0 no tiene sandbox en Linux). Varios proyectos a la vez, en master y aún sin publicar: aceptado en vivo en macOS (Apple silicon) y en Ubuntu (x86_64). En Windows npm rechaza la instalación. macOS en Intel y Linux en arm64 no están probados.
Runtimes
Claude Code, Codex, OpenCode y Pi, cada uno desde una versión mínima. Admitir no es demostrar: una versión queda registrada como verificada en tu máquina con aqorin doctor --live, con tu consentimiento y una llamada al modelo.
Roles restringidos
El sandbox frena las escrituras de un rol de solo lectura o de revisión; sus comandos se le piden al agente, no se hacen cumplir. Ese Run es orientativo.
Recuperación
Al menos una vez. Un paso reiniciado puede repetir un efecto externo que el interrumpido ya tuvo.
Todavía no
jcode como runtime de la alpha, soporte de Windows, y un Runtime Adapter SDK público.

Dónde está

Construido en público, fase a fase, y cada una cerrada contra su propio registro.

  1. Cerrada

    Thesis Validation

    ¿Puede un workflow ejecutarse de forma duradera con varios runtimes y modelos, mezclados en un Run? Validada en parte, y ese veredicto se queda como se registró.

  2. Construida

    Terminal Alpha

    La primera versión que una persona puede usar: una TUI y una CLI sobre cuatro runtimes, en macOS. Su aceptación se recorrió como lo haría alguien nuevo.

  3. Ahora

    Producto después de la alpha

    Una TUI rediseñada, una identidad visual y la guía. @aqorin/cli 0.5.0 está en npm desde el 20-10-2026: ramas y commits en un chat con acceso total (probado en vivo en Claude Code; la configuración y los hooks de git siguen rechazados) y los arreglos de la TUI, sobre el Linux de la 0.4.0 y su propio sandbox. En master, aún sin publicar: un Aqorin sobre varios proyectos, aceptado en vivo en macOS y en Ubuntu.

  4. Después

    Generalización

    jcode, Windows, más Linux (arm64, otras distribuciones) y un SDK público de adaptadores, cada uno afirmado solo cuando esté demostrado.
