§01El problemaref · docs/01-product-vision

      

        
Tu proceso vive en la configuración de un solo agente.

        
Cada agente de código trae sus propios agentes, comandos, skills, hooks y modelo de permisos. Escribe un workflow real —especificar, implementar, revisar, corregir— y solo existirá en un runtime, sostenido por un prompt que le pide al modelo que se acuerde.

§02Cómo funcionaref · docs/30-architecture · docs/33-execution-state

      

        
Aqorin manda en la semántica. Los runtimes, en la ejecución.

        
El Orchestration Engine custodia el Run —su estado, sus políticas, su evidencia— como un log de eventos append-only. Los adapters convierten cada paso en lo que el runtime hace de forma nativa. Cuando un paso intenta atajar, quien dice que no es el reducer, no un prompt.

Rol ≠ Runtime ≠ Modelo

      
Tres conceptos independientes: ningún rol canónico implica un runtime o un modelo. Un Run puede asignar un runtime y un modelo por rol, y Aqorin rechaza el plan cuando no puede hacer cumplir los límites de un rol en su runtime.

    

  


  

    

      
§03Innegociablesref · docs/02-product-principles

      
Reglas para el engine, no reglas que el modelo debería recordar.

      
Son las reglas de diseño sobre las que se construye Aqorin. Algunas ya se aplican en código; el resto son huecos conocidos que se están cerrando.

      

        
01
No toca tu configuración
Aqorin proyecta un overlay aislado, con espacio de nombres propio, junto a tus ficheros. Agentes, comandos, skills, MCP y ajustes nunca se sobrescriben ni se borran.
Dónde vive
Configuration Overlay · adapter

        
02
Conservas tu UX nativa
Sigue usando opencode, pi o codex igual que hoy. Aqorin es opcional, tarea a tarea.
Dónde vive
Por construcción · un CLI aparte

        
03
Invariantes en código
Orden de fases, presupuestos, revisión obligatoria, puertas de aprobación y transiciones legales son cosa de un reducer, no de un system prompt.
Dónde vive
Reducer · packages/core

        
04
El estado es del Run
Una sesión del runtime es un intento, no el Run. Los eventos son durables: si el runtime se cae, lo ocurrido no se pierde.
Dónde vive
Event store

        
05
Garantías honestas
Cada permiso lleva etiqueta: nativo del runtime, aplicado por Aqorin, sandbox del SO, externo… o no aplicable. Nada se eleva en silencio.
Dónde vive
La guía de permisos de cada adapter

        
06
Sin mínimo común denominador
Usa de forma nativa la mejor primitiva de cada runtime, emula con seguridad, degrada de forma visible… o se niega a ejecutar. No se quitan funciones por simetría.
Dónde vive
Negociación de capacidades · engine

§04Hacia dónde varef · docs/exits/README.md · ADR-0049

      

        
Tesis parcialmente validada. Ahora: una alfa que se pueda usar.

        
El Thesis Validation Track preguntaba si un mismo workflow puede ejecutarse de forma durable con distintos runtimes y modelos, mezclados en un mismo Run. La respuesta fue parcialmente validada, y ese veredicto queda tal como se registró. Ahora el track Terminal Alpha construye la primera versión que una persona puede usar: una interfaz de terminal y un CLI, en macOS arm64, sobre Claude Code, Codex, OpenCode y Pi.

Notas de campo · Terminal Alpha2026-10-09

            En curso
            
La base está puesta. Aqorin lista los cuatro runtimes con su versión, su login y sus modelos; sigues un Run en vivo desde otra terminal; un Run continúa aunque cierres la terminal, y un paso atascado espera tu decisión. Al escribir aqorin se abre la interfaz de terminal.

            
Ahora: chat libre con cada runtime a través de Aqorin; Codex ya está, Claude Code es el siguiente. Después, tus propios agentes, skills y MCP, y ejecutar y supervisar todo desde la TUI. Demostrado en macOS arm64; está en main, todavía no en el paquete de npm.

          

          

            
Existe hoy · en main
  • Workflows y roles que escribes tú, ejecutados con aqorin run
  • Un runtime y un modelo por rol, dentro de un mismo Run
  • Rechazo del plan cuando no puede hacer cumplir los límites de un rol
  • Validación decidida por Aqorin, no por el modelo
  • Inventario de cuatro runtimes: versión, login y modelos
  • Runs que sobreviven a la terminal y te esperan si un paso falla
  • aqorin abre una interfaz de terminal que sigue un Run en vivo
  • @aqorin/cli 0.2.0 en npm, MIT, por detrás de main
