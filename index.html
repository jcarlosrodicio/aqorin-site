One workflow. Any coding agent.

Aqorin runs your engineering workflow through Claude Code, Codex, OpenCode or Pi, and keeps the Run, its checks and its evidence. The agent you already use does the work, with its own strengths. Your setup stays yours.

Your process lives in one agent's config folder.

Every coding agent ships its own agents, commands, skills, hooks and permissions. A real workflow (specify, implement, review, fix) ends up written for one runtime and held together by a prompt that asks the model to remember.

In Aqorin the workflow is a file and the runtime is a choice per role. Before anything runs, the plan says which runtime takes each role and what Aqorin can enforce there. What it cannot enforce, it calls advisory.

How a Run goes

Aqorin owns the workflow, the Run's state and its evidence. The runtime owns the execution, in its own way.

  1. 1

    Write the task once

    A task file holds the request and the commands that decide it. The workflow, built in or your own file in your library — one for every project — says which steps run, in what order, and where the work goes back when a review asks for changes. Both are validated and frozen with the Run.

  2. 2

    Checks decide, not the model

    With an Acceptance Plan, Aqorin runs the commands itself and only their exit status decides validation. A step whose checks fail does not pass. Without one, the Run is advisory, and the result says so instead of calling itself validated.

  3. 3

    Agents write inside the Run

    On macOS, and on Linux (with bubblewrap), Aqorin's own sandbox is on by default for Claude Code, OpenCode and Pi, in Runs and in chats. Codex keeps its own sandbox. Where the sandbox cannot be set up, the Run is refused rather than run without it.

    Writes refused

    • The rest of the repository and its .git
    • Your other projects, the ones you added
    • Your keys and credentials
    • Your shell, git and package manager configuration
    • The coding agents' own settings
    • The usual PATH folders, such as /opt/homebrew/bin

    Not limited

    • Reads: a sandboxed agent can still read a secret
    • The network
    • What an MCP server does
    • A project you have not added, caches and temporary files
  4. 4

    The Run outlives the terminal

    Every transition is an event in the Run's own log, checked by the engine's reducer. Close the terminal and the Run is still there: follow it, answer it, resume it, retry or replan a step that failed. Recovery restarts a step, so an effect may repeat.

Rules for the engine, not for a model to remember

  1. Your configuration stays yours

    Aqorin's agents, commands and settings live in its own namespaced overlay. It never writes your runtime's configuration, PATH or symlinks.

  2. Your runtime stays as it is

    Keep running claude, codex, opencode or pi exactly as today. Aqorin is a separate command you use when you want it.

  3. Invariants live in code

    Step order, budgets, required review and legal transitions are enforced by the reducer, not asked of a model in a prompt.

  4. State belongs to the Run

    A runtime session is one attempt. The Run is durable, so a crashed runtime does not erase what happened.

  5. Every guarantee says where it is enforced

    Enforced by Aqorin, by the runtime, by the kernel, or not at all and said advisory. Nothing is elevated silently.

  6. One Aqorin. Multiple projects. Independent workflows.

    Add your projects once and follow them all from one TUI or CLI: Runs of several projects work at once, each on its own runtime, in its own repository, with its own worktrees, sandbox and pull requests, as if each had an Aqorin of its own.

  7. No lowest common denominator

    A runtime's best primitive is used natively, emulated safely, degraded visibly or refused. Features are not dropped for symmetry.

What it does not claim

Said here with the same weight as the features, because you should know before you install.

Platform
Demonstrated on macOS with Apple silicon, and on Linux — Ubuntu 26.04 on x86_64, with bubblewrap as its sandbox and a restricted Claude Code step advisory there — from 0.4.0 (0.3.0 has no sandbox on Linux). Several projects at once, on master and not yet released: accepted live on macOS 27 (Apple silicon; Pi there on a connection of Aqorin's) and on Ubuntu 26.04 (x86_64). On Windows npm refuses the install. macOS on Intel and Linux on arm64 are untested.
Runtimes
Claude Code, Codex, OpenCode and Pi, each from a minimum version. Admission is not evidence: a version is recorded as verified on your machine by aqorin doctor --live, with your consent and one model call.
Restricted roles
A read-only or review role's writes are held by the sandbox; its commands are asked of the agent, not enforced. Such a Run is advisory.
Recovery
At least once. A restarted step may repeat an external effect the interrupted one already had.
Not yet
jcode as an alpha runtime, Windows support, and a public Runtime Adapter SDK.

Where it stands

Built in public, phase by phase, each one closed against its own record.

  1. Closed

    Thesis Validation

    Can one workflow run durably across runtimes and models, mixed in one Run? Partially validated, and that verdict stays as recorded.

  2. Built

    Terminal Alpha

    The first version a person can use: a TUI and a CLI over four runtimes, on macOS. Its acceptance was walked as a new user would.

  3. Now

    Post-alpha product

    A redesigned TUI, a visual identity and the guide. @aqorin/cli 0.5.0 is on npm since 2026-10-20: branches and commits in a Full access chat (run live on Claude Code; git's config and hooks stay refused) and the TUI's fixes, over 0.4.0's Linux and its own sandbox. On master, not yet released: one Aqorin over several projects, accepted live on macOS and Ubuntu.

  4. Later

    Generalization

    jcode, Windows, more Linux (arm64, other distributions) and a public adapter SDK, each claimed only once it is demonstrated.
