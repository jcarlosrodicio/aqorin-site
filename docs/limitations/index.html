Known limitations

Not in the Alpha

Section titled “Not in the Alpha”
  • Platforms: macOS on Apple silicon (Darwin arm64) and Linux as demonstrated — Ubuntu 26.04 on x86_64, from 0.4.0 (0.3.0 predates it). Not demonstrated: Linux on arm64, other distributions, macOS on Intel. Windows is not claimed. On Linux a read-only or review step on Claude Code is advisory, and a few protected names in ~/.claude that do not exist yet cannot be closed.
  • Distribution: npm only (@aqorin/cli 0.5.0); no other package manager or download. 0.4.0 before it brought Linux, 0.3.0 is macOS’s only; 0.1.0 and 0.2.0 are an earlier CLI, without the TUI.
  • Runtimes: Claude Code, Codex, OpenCode and Pi. Other runtimes that Aqorin’s code knows, such as jcode, are not part of the Alpha.
  • Several workflows in one folder: one works in the folder; the others run in git worktrees of their own, at most four at once. Outside git, one at a time. On macOS (and Linux) Aqorin’s sandbox keeps a Run’s agents out of the others’ folders; a Free chat writes in the project folder, where one of them may work; with sandbox: off or on Codex beyond its own sandbox, nothing does.
  • Sandbox: writes only — reads and the network are not limited. On Linux it needs bubblewrap; while a step runs no new name is made at the top of your home, ~/.config or ~/.local; a protected file in ~/.claude that does not exist yet is named as not closed rather than claimed.
  • Free chat: a connection can be chosen on Pi and OpenCode only, and an OpenCode or Pi chat does not show how much context it uses.
  • OpenCode: only OpenAI-compatible providers, as Aqorin connections. OpenCode’s built-in providers (an Anthropic or OpenAI key) and its logins (OpenCode Go, Copilot, xAI) are not reachable from Aqorin.
  • Accessibility: the full-screen TUI does not support screen readers. Use --plain or --json.
  • Notifications: only the terminal bell; no OS notifications.

What it does not claim

Section titled “What it does not claim”
  • Restricted roles are enforced only where a mechanism is validated for that runtime, version, model and platform. Elsewhere they run with an advisory restriction: told not to write or run commands, with the runtime’s own read-only setting, and nothing shows they held to it. Today a few combinations are validated (OpenCode and Claude Code, each with named models), and aqorin eligibility refresh refreshes those two runtimes only. On macOS and Linux with the sandbox on, their file writes are enforced by Aqorin’s sandbox on every runtime but jcode; their commands are not.
  • An agent’s inputs and outputs are added to its instructions, not checked.
  • The model that served a request is not observed on every runtime.
  • A retried step starts over. It is at least once, not a resumed conversation.
  • MCP servers are chosen per agent, but what a server does with its access is not bounded.
  • A runtime’s sandbox — such as Codex’s in a chat — is that runtime’s. Aqorin requests it and checks what the runtime reports, but does not enforce it.

Never, by design

Section titled “Never, by design”
  • Aqorin never writes your runtimes’ configuration, and never loads your Claude Code plugins or Pi extensions — except in a chat you create with Your configuration.
  • It never stores or prints a key’s value, and never signs in for you.
  • It never switches runtime on its own, and retries a step on its own only after a transient failure (a rate limit, an overload, a network fault), twice, while the project is unchanged.
