Connections

Every runtime has a native connection: its own login and configuration, exactly as when you run it yourself.

Aqorin runs Pi and OpenCode isolated, without your extensions or plugins. A provider you reach natively through an extension may therefore not exist inside Aqorin. In that case — or to use an API key instead of a login — add a connection of Aqorin’s own.

Add a connection

Section titled “Add a connection”

On Runtimes (6), select the runtime and press Add connection (a). The form has four steps, and nothing is saved until the last one:

  1. Name — how you will pick the connection.

  2. Endpoint or sign-in:

    • Pi and OpenCode take an endpoint: the base URL of an OpenAI-compatible endpoint, and where its key lives. The URL is https://…, or http:// to this machine only. The key is named by an environment variable’s name, or as a macOS keychain item.
    • Codex and Claude Code take a sign-in: your existing login, or an API key by reference. For Codex, the reference is the name of the variable that holds the key.

    The field asks for the variable’s name — for example NAN_API_KEY, exported in the shell you start aqorin from — never the key itself. If you paste a key’s value there, the form hides it, stores nothing, and says so in one warning. A key that Credentials already lists — an OpenCode provider key or another connection’s, never one only an MCP server uses — is offered by its name and what uses it, to the left of Another environment variable: choose it instead of typing it again. Codex takes environment variables only.

  3. Models: Discover them (one call to the provider’s /models, made only because you asked), type them, or add them later. For Claude Code and Codex, the step also offers their models: the ones the runtime lists for your own sign-in, as Runtimes read them — no model call. With an API key, its account may serve others: type them.

  4. Default model: the model a step gets when it names none. This step shows what will be written.

After it is added

Section titled “After it is added”

The connection appears under its runtime. Its inspector shows:

  • where its key lives, and whether it is set now — checked by its name; the check does not read the value;
  • its models and its default model;
  • who uses it.

Its actions:

  • Edit reopens the same form, filled in.
  • Models makes a model the default, removes one, or adds one by hand — or, on Claude Code and Codex, from the runtime’s own list.
  • Discover asks the provider for its models again.
  • Delete asks first and says what uses the connection. The key stays where it lives.

Aqorin resolves the key only when an attempt runs on the connection. It gives the key to that attempt alone, and scrubs it from everything Aqorin shows or stores.
