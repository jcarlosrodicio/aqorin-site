Modelo de seguridad

La regla de Aqorin es simple: nunca afirma una garantía que no puede aplicar. Cada garantía dice dónde se aplica. Cada alternativa dice en qué se diferencia de ejecutar de forma nativa. Nada se eleva en silencio.

Lo que aplica el motor

Sección titulada «Lo que aplica el motor»

Estas reglas son código del motor de Aqorin, no instrucciones que a un modelo se le pida recordar:

  • Transiciones legales. Un paso se mueve solo por las transiciones de su workflow. Un atajo, como pasar de implement directamente a done, se rechaza.
  • Validación. Con comprobaciones, Aqorin ejecuta tus comandos por sí mismo, sin shell, y solo su código de salida decide.
  • Revisión y presupuestos. Un Run termina con éxito solo cuando su revisión requerida está aprobada, sus comprobaciones han pasado, sus aprobaciones están resueltas y no se ha superado ningún presupuesto.
  • Human Approval (aprobación humana). Lo que necesita tu aprobación la espera. --yes nunca aprueba nada.
  • Admisión antes de que se ejecute nada. Un plan que no se puede cumplir se rechaza antes de que arranque ningún runtime.

Roles restringidos

Sección titulada «Roles restringidos»

Un agente read_only o review se admite solo donde Aqorin ha validado el mecanismo que lo restringe, para ese runtime, versión, modelo y plataforma. En cualquier otro sitio, el plan se rechaza (policy_unenforceable), nunca se relaja. Aqorin nunca amplía la clase de acceso de un rol para que un runtime encaje.

Un workflow que no puede cumplir esto se etiqueta como advisory (orientativo), y su resultado nunca se presenta como revisado de forma independiente.

Tu configuración y tus claves

Sección titulada «Tu configuración y tus claves»
  • Aqorin nunca escribe la configuración de tus runtimes. Lo que le da a un runtime es un entorno aislado, con espacio de nombres propio, para un intento.
  • Las claves se guardan solo por referencia: el nombre de una variable o un elemento del llavero de macOS. El valor de una clave se resuelve cuando se ejecuta un intento, se le da únicamente a ese intento, y se borra de todo lo que Aqorin muestra o registra. Aqorin nunca almacena, imprime ni lee el valor de una clave.
  • Aqorin nunca inicia sesión por ti, y nunca lee los archivos de credenciales de un runtime.

Dónde se aplica cada garantía

Sección titulada «Dónde se aplica cada garantía»
Aplicada por Ejemplo
Aqorin Transiciones, presupuestos, comprobaciones, aprobaciones, admisión, referencias de credenciales.
El runtime, de forma nativa Los avisos de permiso propios de un runtime, y su propio sandbox, como el de Codex en un chat.
No aplicable Se dice como tal. Aqorin lo solicita, y dice que solo lo solicitó.

Una marca de sandbox que Aqorin no ha verificado en un runtime se informa como una petición, no como una garantía.

Free chat

Sección titulada «Free chat»

Un Free chat se ejecuta como lo hace su runtime en su propia terminal.

  • En Ask, el runtime te pregunta lo que te preguntaría en su terminal.
  • En Full access, ejecuta cualquier comando y edita cualquier archivo sin preguntar. Tú confirmas este modo al elegirlo.
  • Con Your configuration, todo lo que tus ajustes ya permitan se ejecuta sin preguntar.

Mira Free chat.

Lo que Aqorin no acota

Sección titulada «Lo que Aqorin no acota»
  • Lo que hace un servidor MCP con su acceso. Aqorin elige qué servidores y herramientas puede usar un agente, no lo que hace el servidor.
  • Tus comandos de comprobación. Se ejecutan con tus permisos. Son código en el que confías.
  • Un rol que puede editar archivos. Puede hacer en el proyecto todo lo que su runtime permita.
